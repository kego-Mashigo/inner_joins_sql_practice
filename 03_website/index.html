01 — Learn

The JOIN family

A JOIN allows you to bring related data together from two or more tables. The main difference between JOIN types is which rows are kept in the result.

01

INNER JOIN

Returns only rows where a match exists in both tables.

  • Best for matching records
  • Unmatched rows are removed
Explore
02

LEFT JOIN

Returns every row from the left table and matching rows from the right.

  • All left rows remain
  • Missing right values become NULL
Explore
03

RIGHT JOIN

Returns every row from the right table and matching rows from the left.

  • All right rows remain
  • Missing left values become NULL
Explore
04

FULL OUTER JOIN

Returns matched rows plus unmatched rows from both tables.

  • Keeps both sides
  • Unmatched columns become NULL
Explore
05

CROSS JOIN

Creates every possible combination of rows between two tables.

  • No matching condition required
  • Can create many rows
Explore
06

SELF JOIN

Joins a table to itself, usually to compare related rows within the same table.

  • Uses table aliases
  • Useful for hierarchies
Explore
02 — JOIN TYPES

INNER JOIN

Think: “Only give me the records that match.”

Result idea
Customers
MATCH
Orders

Only the overlapping relationship is returned.

SELECT C.customer_id, C.customer_name, O.order_id FROM customers AS C INNER JOIN orders AS O ON C.customer_id = O.customer_id;
Use it when: you only need records that exist in both tables.
03 — JOIN TYPES

LEFT JOIN

Think: “Keep everything from my left table.”

SELECT C.customer_id, C.customer_name, O.order_id FROM customers AS C LEFT JOIN orders AS O ON C.customer_id = O.customer_id;
Important idea

If a customer has no matching order, the customer still appears. The order columns will contain NULL. This makes LEFT JOIN useful for finding records with no match.

04 — JOIN TYPES

RIGHT JOIN

Think: “Keep everything from my right table.”

SELECT C.customer_id, C.customer_name, O.order_id FROM customers AS C RIGHT JOIN orders AS O ON C.customer_id = O.customer_id;
Important idea

Every row from the right table is retained. If no matching row exists on the left, the left-side columns become NULL.

05 — JOIN TYPES

FULL OUTER JOIN

Think: “Keep everything from both tables.”

SELECT C.customer_id, C.customer_name, O.order_id FROM customers AS C FULL OUTER JOIN orders AS O ON C.customer_id = O.customer_id;
Important idea

Matching rows are combined, while unmatched rows from either table are also returned. Missing values appear as NULL.

06 — JOIN TYPES

CROSS JOIN

Think: “Give me every possible combination.”

SELECT C.customer_name, P.product_name FROM customers AS C CROSS JOIN products AS P;
Row multiplication

If the first table has 4 rows and the second has 3 rows, a CROSS JOIN can produce 4 × 3 = 12 combinations.

07 — JOIN TYPES

SELF JOIN

Think: “Compare rows inside the same table.”

SELECT E.employee_name AS employee, M.employee_name AS manager FROM employees AS E LEFT JOIN employees AS M ON E.manager_id = M.employee_id;
Why the aliases?

The same table is used twice, so aliases such as E and M let SQL distinguish the two roles.

11 — CHEAT SHEET

Remember it quickly

INNER = Match

Only rows that match on both sides.

LEFT = Keep left

Everything on the left, plus matches from the right.

RIGHT = Keep right

Everything on the right, plus matches from the left.

FULL = Keep both

All rows from both tables.

CROSS = Combine all

Every possible combination.

SELF = Same table

Compare or relate rows within one table.

The JOIN formula
SELECT columns FROM table_a AS A [JOIN TYPE] table_b AS B ON A.key = B.key;

Start by asking: Which table's rows must I keep? That question often tells you which JOIN to choose.
